# 中文改稿修订说明

本轮重写保留实际运行接口、预算、quality gate、冻结规则和职责边界。以下说明哪些地方是有意编辑，哪些是独立审查发现后补回的语义。

## 1. 有意的文字与组织调整

| 调整 | 原因与保留条件 |
|---|---|
| 研究配方、构造示例和延伸参考改为按需查阅 | 避免固定研究路线；操作接口、权限和评估契约仍在执行前核对 |
| 角色目标／可用能力与共享协议分开 | 启动消息不重复完整角色和预算；共享规则必须显式可达并阅读 |
| Engineer 的 selection_rationale 从“1–3句”改为简要说明 | 保留成本、端到端影响、改动和预期，不限制表达句数 |
| 固定 1800 秒工具参数改为当前环境支持的阻塞等待 | 保留 terminal wait、原 ID 重连、status/recover 和避免重复执行／短轮询的目的 |
| 共享规则不再把 v3 文档表述写成所有 run 的版本事实 | 当前任务与保存契约权威；阈值和已有历史版本不变 |
| 单纯超参数搜索列为非优先方向，强调组合／迁移／adaptive | 来自用户本轮明确研究倾向；保持偏好，不升级为硬禁令 |
| 取消按角色编号步骤安排所有调查的启动措辞 | 登记、冻结和状态依赖仍按协议；实验选择、诊断顺序与深度自主 |

## 2. Astra 第一轮发现后的修复

| 审查项 | 当前处理 |
|---|---|
| B1：Researcher 设计含义弱化 | 增补四字段内容表：实际通信、聚合／同步、optimizer/state、回应问题的组件、竞争解释、原组件价值与副作用、可证伪预期及支持／削弱结果 |
| B2：Memory runtime 归因边界松动 | 恢复不从 Research Analysis 推断 runtime 原因，实现归因依据 Engineering Analysis |
| G1：按需参考可能吞掉操作契约 | 规则区分研究配方与操作接口；register 前核对必填字段和契约，方法实现验证矩阵／卷积支持 |
| G2：Analyzer 语义链与状态标注不足 | 补实际通信到 optimizer update 的追踪、故意改变／无法恢复状态、主张涉及的阶段与交互、动作与时机影响的区分 |
| G3：共享边界精度 | 明确 lease 命令参考、timing 的新／legacy 范围、上传者认证／声明 SHA／内容 hash 与执行认证的区别；删除初稿额外加入的持锁等待 GPU 限制 |
| G4：启动去重后的阅读依赖 | 明确执行前阅读共享 workflow，具体操作核对接口与契约 |
| G5：Engineer profiler 限制过窄 | 去掉“重叠的”限定，不能用 profiler 时长之和充当正式 step time；JSON 显式仅含规定四字段 |

此外明确复用训练前缀要求行为与必要状态一致，避免把前缀缓存或换方法续训当作无条件等价。

## 3. 本轮验证边界

原文与当前实际运行源文件按七份 SHA-256 快照核对；中文稿检查文档链接、格式、命令名及 Analysis／Memory schema 词项。Astra medium 独立核对语义与上下文可达性，并比较改前后版本。

本轮未替换实际生成器或 task prompt，未改变 legacy 删除状态，也未运行 GPU、Agent A/B 或生产投递测试。Startup 仅作为生成设计稿比较；文字更清楚不等于已经证明实际研究表现或 token 效率提高。

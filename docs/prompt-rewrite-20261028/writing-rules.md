# CORAL AutoResearch prompt 写作规则

这组规则用于修改和新写 CORAL AutoResearch 的角色、分析、知识整理和启动 prompt。目标是让 Agent 理解要解决的问题、可用条件和期望交付，并在这些条件内作出研究判断。精简以清晰和可执行为准，不以字数最少为准。

## 1. 先说明目的和期望结果

每个角色先说明背景、职责、要解决的问题和交付。较大的 section 先交代这一阶段要完成什么，再介绍可用能力和判断依据。

- 不用“自主研究”“认真分析”等抽象要求代替具体目的。
- 不把输出字段名当作角色目标；说明字段承载什么判断和价值。

## 2. 给出输入和参考地图

说明已有代码、研究档案、证据、参考资料分别能帮助解决什么问题，并指出权威来源。重要结论能追溯到原始证据。

执行前确认相应操作接口、权限和当前评估契约，使实际调用符合约定。

- 研究配方、算法示例和延伸参考按需使用，不把阅读顺序、算法目录或诊断清单变成必经研究路线。
- 区分初始 Spec、当前研究记录、选定 iteration 和实际固定 SHA。
- 对缺失和未提供的资料明确范围，不要求 Agent 读取其上下文无法访问的资料。

## 3. 保留用户的研究倾向及其强度

显式保留选题、Parent 选择、探索路线和研究内容的偏好。使用“优先”“倾向”“可考虑”等与原意一致的措辞。

本轮需要保留的倾向包括：Parent 选择重视研究价值、连续性、信息增量和验证成本，优先评估 Parent handover；当前优先低秩与稀疏化；REFINE 深入或挑战 Parent；EXPLORE 倾向于区别于 Parent 及现有分支的技术路线，包括低秩、稀疏、量化、局部或去中心化通信；重视有动机的组合、迁移、dynamic/adaptive 机制；参数调整服务于研究问题，单纯超参数搜索不是优先方向。

- 不把偏好升级为硬禁令，也不把明确偏好改成泛泛的“自行选择”。
- 不把 Researcher 的路线偏好强加给独立 Analyzer 的结论。

## 4. 自主权需要有可执行的能力边界

说明 Agent 可以做哪些事、这些操作用于什么目的、适用条件是什么。例如：在固定开发数据上迭代；按需暂停训练做诊断；在训练前、暂停后或完成后测时；根据证据继续、修订或停止。

- 不将自主权简化为“按这些编号步骤执行”。
- 不因去微操而省掉阶段之间真实存在的依赖。
- 可选诊断、profiling 或开发 timing 不变成每轮必做或候选提名门槛。

## 5. 必须执行的操作给出真实命令

登记、训练、记录判断、追加设计、提名候选、工程测时和提交 Analysis 等关键操作给出实际命令；复杂请求字段和完整示例链接到对应参考。

- 区分“保存判断”和“执行动作”，例如 `decision` 不会自动继续训练。
- 区分“提交已持久化”和“发布已完成”，例如 `finalizing`。
- 不发明命令、字段、权限或恢复能力。

## 6. 用目的约束研究质量

要求证据足以回答研究问题、区分关键解释、判断实际质量与成本。让 Agent 自主选择日志、推导、检查、受控实验及其顺序。

- 不规定每次都走同一套假设、诊断或 profiling 路线。
- 保存原预测和修订原因，保留失败、反证、意外收益和重要未知。
- 区分机制解释与实际价值，不以机制已被确认作为额外晋级门槛。

## 7. 要求写正文，约束作 bullets

正文说明任务、目的、操作和交付；较长内容用小标题分组。条件、禁止事项、硬上限和容易误解的边界用 bullets，并紧邻其约束的操作。资料映射、能力和输出字段适合使用表格。

- 避免一个大 section 下堆成长段。
- 避免每句话都列为 bullet，导致主次和因果关系消失。
- 不为符合模板而制造无内容的小节。
- 将已确认稿翻译为英文时，保留标题层级、段落分组、正文与 bullets 的划分；翻译不再重新编辑结构。“可”“优先”“无须”“禁止”等措辞也保持原有强度。

## 8. 按职责分配规则

启动入口负责身份、位置、当前状态和角色入口；角色正文负责目标、研究倾向、能力和交付；共享 workflow 负责跨角色协议；命令参考负责接口细节；宿主负责计数、调度、状态和发布。

- 同一角色的启动消息与 AGENTS 不重复注入完整角色和完整预算表。
- Analyzer、Memory 等独立会话必须拥有自身所需的边界和输出契约，不能假定它们读取共享 workflow。
- 允许为保证可达性重复关键边界；删除的重复项必须仍有明确承载位置。

## 9. 保留系统接口和非显然约束

预算、冻结、评估数据隔离、托管 GPU、幂等、恢复、证据身份和 schema 属于执行协议。通过宿主状态和角色可达资料清楚表达其真实含义。

- 不借文字重写改变预算、quality gate、Parent 资格、角色权限、schema 或评估协议。
- 区分同 SHA 精确续跑、新设计从头训练和基础设施恢复；区分开发与 Final timing。
- 跨版本运行服从其保存契约，不能以新的文档重标历史结果。
- 工具等待参数可改为“使用当前环境支持的阻塞等待”，同时保留避免重复执行和无意义轮询的目的。

## 10. 让知识输出体现增量和范围

保留真正能影响设计、实验或实际判断的发现、反例和可靠效果。相同认识合并证据，冲突应收窄、修订或撤回旧结论。

- 不要求每个 Node 都有新发现、每次填满问题额度或每次更新 wisdom。
- 重复次数不自动提高结论的普遍性；继承覆盖不等于重新检查。
- 不用运行状态、泛泛局限或格式检查充当机制发现。

## 11. 用覆盖清单审核改写

逐项核对原文的任务要求、硬约束、研究倾向、可选能力、必要命令和输出契约。每项说明新稿的承载位置，或为何由可达的其他输入承载。

- 检查遗漏、弱化、无意强化、不可达引用和新旧矛盾。
- 先确认原文是否与当前契约一致，不能把原文已有的版本错误当成必须保留的要求。
- 长度变化只作辅助信息；中英文长度不可直接当作上下文节省比例。

## 12. 区分文字评审与运行效果

比较改前后的清晰度、可执行性、语义覆盖、自主判断空间和维护成本。涉及实际 Agent 表现的结论，需要另行进行运行比较。

- 文字审核不证明实验结果、研究质量或 token 使用得到改善。
- 本轮保存中文评审稿和原文快照；实际替换入口时需同时校验投递内容、引用与原有检查。

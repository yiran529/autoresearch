# Evaluation tasks and compression policy
The recorded evaluation contract is authoritative. Contract v4 separates **Development experiments** from **Final evaluation**; saved v1/v2/v3 runs retain their original behavior and references. Never relabel historical results or invent reference hashes. New-contract scoring requires newly established matching dense/Root evidence; historical seed results are not authoritative references.
## Fixed training tasks
| Phase/task | Fixed training settings | Quality evidence |
| --- | --- | --- |
| Development experiments: `llama130m_muon` | Llama130M, Muon, BF16, seed 1243, sequence length 256, per-device batch 128, 4000 updates within the fixed 20000-step schedule; matrix LR 0.01, scalar LR 0.001, activation checkpointing | Completed final loss / same-contract dense final loss <= 1.05 |
| Final evaluation: `llama60m_adamw` | Llama60M, AdamW, BF16, seed 1243, sequence length 256, per-device batch 128, 5000 updates within the fixed 8393-step schedule; LR 0.0025, activation checkpointing | Completed final loss / same-contract dense final loss <= 1.05 |
| Final evaluation: `resnet18_cifar100_muon` | ResNet18/CIFAR100, 40 epochs / 14080 updates, 4 GPUs, batch 32 per GPU, 2 workers, FP32, Muon matrix LR 0.02 / scalar LR 0.0005, weight decay 0.0005, seed 1243, epoch cosine schedule, no LR warmup | Final-epoch accuracy on 5000 fixed validation images from official training data; default drop <= 1.0 percentage point against same-contract dense, operator configurable; no best-epoch selection |
Vision optimizer/augmentation settings inherit CIFAR100 CM046/CM047; v3 changes the data protocol. Split official training data by class with a local RNG seeded 1243: shuffle each class in ascending label order, reserve its first 50 indices, and sort the resulting train/validation index lists. This gives 45000 training and 5000 validation images. Train alone uses random crop/flip; validation uses only tensor conversion/normalization. Both arms use identical split hashes and the fixed 40-epoch schedule. Daily evaluation never loads official test data. Compression choices belong to the candidate.
After search ends, the operator can freeze a few candidates and retrain with the same 45000-image recipe for one-off official-test confirmation. The seed runner supports `--evaluation-split test --validation-per-class 50 --split-seed 1243`; this does not authorize Researcher GPU work outside managed entrypoints or add a per-Node test stage. Keep that confirmation separate from search feedback.
Root bootstrap evaluates the already-fixed baseline A0 on all three quality tasks and fresh formal timing under this same contract. It has no development/selection loop. Establish matching dense references and reevaluate Root after a budget/contract change; do not reuse old scores by replacing their hash. Saved runs retain their recorded contract and budgets.
## Candidate-owned method adaptation
- Define the per-workload compression settings/mapping, including any state-dependent policy, before Final evaluation; verify support for matrix and convolution gradients.
- Stock GreedyLoRE vision rank 64, dense prefix 4000 updates and refresh gap 1200 are method defaults only. They are not fixed constraints on candidate rank, compression start, refresh, communication or adaptive policy. Declare candidate choices and effective timing cycles/events consistently.
- The policy receives compression parameters only; returning training fields is rejected. Dense references keep compression disabled. Candidate policy must not change fixed data, training budget, optimizer, seed, precision or evaluation settings.
## Final evaluation and recovery
- `research finish` requires completed passing development validity/quality/resource evidence only. Development timing remains optional. Freeze the selected SHA/design/policy/workload mapping first; run fresh mandatory final timing and both final quality tasks afterward, without reopening development or tuning from feedback.
- Fixed timing uses Llama350M/AdamW, BF16 and FP32, four GPUs, batch 1 per GPU, the contract’s repetitions and complete-cycle policy. Preserve timing validity, event and hardware-comparability checks. Timing magnitude introduces no new promotion gate. Saved v1/v2/v3 contracts retain Llama130M timing; never reuse their timing as a 350M reference.
- Optional development timing has cumulative limits of 5 completed / 15 total executions. Mandatory final timing is separate and cannot reuse development measurements. Completed final-component results may be reused only to recover that same frozen evaluation.
- Default infrastructure retry limit is 2 per final component; retain other completed components. Vision retries start from scratch, with no exact checkpoint-resume claim. Retain failures and all measured results. All final components must be terminal or explicitly skipped before independent Analysis and quality-gated Engineering start.
- Final results describe transfer/robustness of a development-selected method. Their reuse by later Nodes makes them available research evidence rather than independent campaign-level held-out evidence.

## Advisory utility
Contracts v3/v4 use `U = S * exp(-mean(candidate_loss - Root_loss over the two language tasks))`, version `mean-log-ppl-ratio-v2`. Changes are signed: language improvements raise U and regressions lower it. S keeps its existing stage-matched Root timing reference. Vision validation accuracy stays outside U and retains its independent quality gate. U is advisory, never a promotion/selection gate. Saved v1/v2 contracts keep `worst-ppl-discount-v1`; historical Attempts are never rewritten.
